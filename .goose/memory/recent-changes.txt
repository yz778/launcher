# history ui-improvements command-building
**History Manager Enhancement**: Modified history manager to record complete matched application names instead of partial user input.

**Key Changes**:
1. **New Method**: Added `_build_executed_command()` in LauncherWindow to construct the full command/application name
2. **Logic**: 
   - Uses `result.name` as base command for most plugins
   - Handles special cases for terminal, calculator, executable, and desktop_file plugins
   - Preserves additional arguments from user input when applicable
3. **Example**: User types "work" and matches "workspace" → history now stores "workspace" instead of "work"
4. **Benefits**: More accurate history that shows what was actually launched rather than partial input strings

**Technical Details**:
- Modified `execute_result()` method to call `_build_executed_command()` instead of using raw user input
- Plugin-specific handling ensures appropriate command representation for each plugin type
- Maintains argument preservation for commands that accept additional parameters

# history extensible-design metadata-based
**Final History Manager Fix**: Replaced hardcoded plugin names with extensible metadata-based approach.

**Final Implementation**:
```python
def _build_executed_command(self, result: SearchResult) -> str:
    # Check if plugin provides a specific command in metadata
    if "command" in result.metadata:
        command = result.metadata["command"]
        # Add any arguments if present
        args = result.metadata.get("args", [])
        if args:
            command = command + " " + " ".join(args)
        return command
    
    # Fallback to result name
    base_command = result.name
    
    # Add any arguments if present in metadata
    args = result.metadata.get("args", [])
    if args:
        base_command = base_command + " " + " ".join(args)
    
    return base_command
```

**Benefits**:
- **Extensible**: Any plugin can provide `"command"` in metadata to control history storage
- **Lightweight**: No hardcoded plugin names - only 20 lines of code
- **Backward Compatible**: Falls back to `result.name` if no command specified
- **Plugin-Agnostic**: Works with any current or future plugin that follows the metadata pattern

**How it works**:
- Terminal plugin: Uses `metadata["command"]` (actual command after `>`)
- Executable plugin: Uses `metadata["command"]` + `metadata["args"]`
- Other plugins: Fall back to `result.name` + `metadata["args"]` if present
- Future plugins: Just add `"command"` to metadata to customize history storage

# plugin-configuration history-tracking extensible
**Plugin History Tracking Configuration**:

**Feature**: Added configurable `track_history` option to each plugin to control whether executions are stored in history.

**Implementation**:
1. **Base Plugin Class**: 
   - Added `track_history: True` to base defaults
   - Added `should_track_history()` method
   - Modified `get_config_defaults()` to merge base + plugin defaults
   - Added abstract `_get_plugin_config_defaults()` method

2. **Plugin-Specific Defaults**:
   - **Calculator**: `track_history: False` (don't track calculations)
   - **Qalculate**: `track_history: False` (don't track calculations) 
   - **Executable**: `track_history: True` (default, track commands)
   - **Desktop File**: `track_history: True` (default, track apps)
   - **Terminal**: `track_history: True` (default, track commands)

3. **SearchResult Metadata**: Each plugin adds `"track_history": self.should_track_history()` to result metadata

4. **Launcher Window**: Checks `result.metadata.get("track_history", True)` before storing to history

**Configuration**:
Users can override in config file:
```yaml
calculator:
  track_history: true  # Override default to track calculations

executable:
  track_history: false  # Override default to not track executables
```

**Benefits**:
- **No hardcoding**: Everything controlled by plugin configuration
- **Extensible**: Any plugin can set its own default and users can override
- **Clean calculator history**: Calculator results don't clutter history by default
- **Configurable**: Users can enable/disable history tracking per plugin

# simplified plugin-configuration history-tracking
**Simplified Plugin History Tracking** (Fixed):

**Problem**: Original implementation added unnecessary abstraction layer with `_get_plugin_config_defaults()`.

**Solution**: Directly added `track_history` to existing `get_config_defaults()` method in each plugin.

**Final Implementation**:
1. **Base Plugin**: Just has `should_track_history()` method and `__init__()`
2. **Each Plugin**: Includes `track_history` directly in their existing `get_config_defaults()`:

```python
# Calculator & Qalculate
def get_config_defaults(self) -> Dict[str, Any]:
    return {
        "track_history": False,  # Don't track calculations
        # ... other plugin-specific config
    }

# Executable, Terminal, Desktop File  
def get_config_defaults(self) -> Dict[str, Any]:
    return {
        "track_history": True,  # Track commands/apps
        # ... other plugin-specific config
    }
```

**Benefits**:
- ✅ **Simple**: No extra abstraction layers
- ✅ **Clear**: Each plugin explicitly sets its own defaults
- ✅ **Maintainable**: Uses existing patterns
- ✅ **Extensible**: Future plugins just add `track_history` to their existing config defaults

**User Configuration**: Same as before - users can override any plugin's `track_history` setting in config file.
