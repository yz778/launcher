# technical implementation architecture dependencies
Launcher Technical Implementation Details:

**Singleton Management**:
- Unix socket at /tmp/launcher.sock
- IPC commands: SHOW, RESCAN, RESCAN_PLUGIN
- C implementation for ultra-fast toggle (toggle.c)
- Python fallback (toggle.py) with same functionality

**Plugin Architecture**:
- ABC-based Plugin interface with SearchResult data structure
- Plugin discovery via module inspection
- Thread pool executor for concurrent searches (8 workers)
- Plugin lifecycle: load → initialize → start → search/execute → cleanup

**Search System**:
- Non-blocking searches with result callbacks
- Search ID tracking to handle stale results
- GLib.idle_add for thread-safe UI updates
- StringMatcher utility for fuzzy matching

**UI Framework**:
- GTK 3.0 with PyGObject bindings
- CSS theming with default + user overrides
- LauncherWindow with entry field and scrollable results
- Keyboard navigation and shortcuts

**Configuration Management**:
- YAML-based with XDG directory compliance
- Recursive config loading (defaults + user overrides)
- Plugin-specific config sections
- Runtime config validation and defaults

**Dependencies**:
- PyGObject>=3.40.0 (GTK bindings)
- pyxdg>=0.28 (desktop file parsing)
- PyYAML>=6.0 (configuration)
- sympy>=1.10.1 (calculator plugin)
- pyperclip>=1.8.0 (clipboard support)
- xdg-base-dirs>=6.0.0 (XDG compliance)

**Performance Features**:
- Lazy module imports for faster startup
- Background plugin initialization
- Resource cleanup on shutdown
- Memory-efficient search result handling

# icon-storage performance history executable-plugin
**Icon Storage and Performance Improvements**:
- **History Icon Storage**: Modified HistoryManager to store actual icon data (base64 encoded PNG) for executable plugin items in history file
- **Icon Data Methods**: Added _pixbuf_to_base64() and _base64_to_pixbuf() for converting between pixbuf and storage format
- **Enhanced History Display**: Modified LauncherWindow to prioritize stored icons for executable plugin items in history view
- **Performance**: No need to re-search plugins for icons when showing history - icons are restored from cached data
- **Executable Plugin Focus**: Icon storage specifically targets executable plugin items which often have custom #icon directives
- **Backward Compatibility**: No backward compatibility maintained (as requested) - new format stores icon_data field for executable items
