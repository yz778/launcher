# workflow development patterns performance
Launcher Development Workflow & Key Patterns:

**Startup Process**:
1. Singleton check via Unix socket (/tmp/launcher.sock)
2. Fast UI creation with minimal config
3. Background async initialization of plugins
4. Thread pool for concurrent plugin searches

**Plugin Development Pattern**:
- Inherit from plugins.base.Plugin ABC
- Implement: get_id(), get_name(), get_description(), get_config_defaults()
- Initialize() for config/CSS, start() for heavy setup
- search() returns List[SearchResult], execute() handles actions

**Performance Optimizations**:
- Lazy imports for faster startup
- Background plugin initialization
- Thread pool for searches (max 8 workers)
- Ultra-fast toggle via C binary (50ms timeout)
- Singleton pattern prevents multiple instances

**Configuration System**:
- Layered config: defaults + user overrides
- YAML format in ~/.config/launcher/config.yaml
- Plugin-specific configuration sections
- CSS theming support with defaults + user overrides

**Recent Development Focus** (from git log):
- History management and UI integration
- Thread pool optimization for plugin searches
- Resource cleanup and memory management
- Icon handling improvements (current 'icon' branch)

**Build & Setup**:
- ./setup.sh: Creates venv and installs dependencies
- ./build_toggle.sh: Compiles C binary for fast toggling
- Development install via 'uv pip install -e .'
